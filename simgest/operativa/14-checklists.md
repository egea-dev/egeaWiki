## 14. Listas de comprobación

Las listas de comprobación no sustituyen la lectura de los procedimientos. Se utilizan al final de una tarea para confirmar que no se ha omitido ningún control crítico.

> **Objetivo**
>
> Aplicar una revisión breve, repetible y documentada antes de emitir, confirmar o cerrar los procesos principales.

## Cómo utilizar estas listas

Estas listas están diseñadas para una comprobación final y no para reconstruir el procedimiento desde cero. Si un usuario no conoce el significado de una casilla, debe abrir la entrada correspondiente antes de marcarla. La lista debe utilizarse sobre el registro real de SIMGEST, el documento físico o el PDF generado, según el proceso. No es suficiente confirmar verbalmente que “está revisado”.

1. Complete primero el procedimiento correspondiente.
2. Revise cada punto sobre el documento real.
3. No marque una casilla por recuerdo.
4. Detenga el proceso si un punto no puede confirmarse.
5. Registre la incidencia.
6. Repita la lista después de corregir.

Una casilla marcada significa que el dato ha sido comprobado, no que el campo contiene cualquier valor.

## Antes de emitir un presupuesto

### Identificación

- [ ] Cliente correcto.
- [ ] Referencia clara y reconocible.
- [ ] Proyecto informado.
- [ ] Fecha y versión correctas.
- [ ] Dirección revisada cuando proceda.

### Condiciones

- [ ] Tarifa correcta.
- [ ] Forma de pago pactada.
- [ ] Descuentos revisados.
- [ ] IVA correcto.
- [ ] Notas necesarias conservadas.

### Líneas del pedido a proveedor

- [ ] Todos los artículos son referencias reales.
- [ ] Descripciones comprensibles.
- [ ] Cantidades y unidades revisadas.
- [ ] Medidas confirmadas.
- [ ] Colores, acabados y variantes correctos.
- [ ] Precios comprobados.
- [ ] No hay líneas duplicadas.
- [ ] Los conceptos con importe no están solo en notas.

### Documento PDF

- [ ] PDF generado después del último guardado.
- [ ] Cabecera coincide con la oferta.
- [ ] Todas las líneas aparecen.
- [ ] Totales e impuestos coinciden.
- [ ] Forma de pago visible y correcta.
- [ ] Todas las páginas son legibles.
- [ ] No hay texto cortado ni columnas superpuestas.

## Antes de confirmar una oferta como pedido

- [ ] Se está utilizando la versión aprobada.
- [ ] La revisión del presupuesto está completa.
- [ ] El PDF validado corresponde a la oferta.
- [ ] Cliente, proyecto y referencia son correctos.
- [ ] No existen dudas comerciales abiertas.
- [ ] Se conoce el efecto de la confirmación.
- [ ] La acción está autorizada.

El procedimiento exacto de aprobación del cliente y la evidencia necesaria son **Pendiente de validación por Hacchi**.

## Antes de generar un pedido a proveedor

### Origen y alcance

- [ ] Pedido de cliente en estado requerido.
- [ ] Proyecto identificado.
- [ ] Filtros comprobados o líneas revisadas individualmente.
- [ ] No hay necesidades de otros proyectos.

### Líneas

- [ ] Tela y compraventa están separadas.
- [ ] Todos los artículos son correctos.
- [ ] Variantes y unidades coinciden.
- [ ] Cantidades agrupadas verificadas.
- [ ] No se incluyen cantidades ya pedidas.

### Proveedor y tarifa

- [ ] Todas las líneas tienen proveedor.
- [ ] Proveedor habitual comprobado.
- [ ] Tarifa oficial revisada.
- [ ] Precio y unidad coinciden.
- [ ] Vigencia y moneda revisadas.

### Generación

- [ ] Modalidad de pedido validada.
- [ ] Mensajes del sistema leídos.
- [ ] Pedido generado abierto.
- [ ] Cabecera y líneas comprobadas.

## Antes de confirmar una recepción

### Identificación de la recepción

- [ ] Proveedor correcto.
- [ ] Pedido correcto.
- [ ] Número de albarán disponible.
- [ ] No existe un albarán duplicado.

### Mercancía

- [ ] Artículo y variante identificados.
- [ ] Unidad correcta.
- [ ] Cantidad física contada o medida.
- [ ] Cantidad introducida en la línea correcta.

### Escenario

- [ ] Recepción completa o parcial identificada.
- [ ] **Pedido servido** solo está marcado cuando corresponde.
- [ ] El exceso de cantidad tiene validación.
- [ ] El cierre manual tiene autorización.

### Resultado

- [ ] Albarán interno generado.
- [ ] Número del proveedor registrado.
- [ ] Stock comprobado.
- [ ] Material asignado cuando corresponde.
- [ ] Cantidades pendientes siguen abiertas.
- [ ] Indicador **Falta tela** revisado.

## Antes de cerrar una revisión de datos migrados

- [ ] Versión de origen identificada.
- [ ] Códigos y cuentas comparados.
- [ ] Formas de pago mapeadas.
- [ ] Localidades comprobadas.
- [ ] Valores provisionales registrados.
- [ ] Roles de tercero separados.
- [ ] Punto de corte comunicado.
- [ ] Incidencias prioritarias revisadas.
- [ ] Correcciones comprobadas después de guardar.
- [ ] Continuidad con otra empresa aprobada.

## Antes de considerar una carga preparada

- [ ] Cliente, documento y referencia correctos.
- [ ] Líneas completas.
- [ ] Cantidades físicas revisadas.
- [ ] Bultos identificados.
- [ ] Peso y palés revisados cuando proceda.
- [ ] No hay documentos ajenos.
- [ ] Entregas parciales validadas.
- [ ] Criterio de cierre confirmado.

## Registro de incidencias durante la checklist

Cuando una casilla no pueda marcarse, anote el documento, el campo afectado, el valor encontrado y la acción pendiente. No continúe con el resto del proceso suponiendo que la incidencia se corregirá después. Las dudas funcionales deben quedar identificadas con la fórmula obligatoria **Pendiente de validación por Hacchi**.

## Evidencia de finalización

Una tarea se considera revisada cuando existe un resultado verificable:

- oferta guardada;
- PDF validado;
- pedido generado y abierto;
- albarán revisado;
- stock comprobado;
- incidencia registrada;
- ficha corregida y vuelta a abrir.

Marcar una lista sin conservar ninguna evidencia no sustituye la comprobación del documento.
